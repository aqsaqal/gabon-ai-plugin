# ВОР: ведомость объёмов работ

ВОР — список работ с единицами и количествами, без цен. Каждое количество должно быть
проверяемым: формула из размеров, ссылка на документ и статус. Скрипты в `scripts/`
рядом с этим файлом.

## Шаг 1. Прочитай документы заказчика

```bash
uv run <папка навыка>/scripts/extract_docs.py projects/<объект>/input/ --out projects/<объект>/input/_text
```

Скрипт создаёт текстовые копии PDF, DOCX и XLSX с метками страниц, листов и таблиц.
Страницы без текста (сканы, чертежи) он перечисляет отдельно: открой их как изображения.
Файлы .doc и .xls попроси пересохранить в DOCX и XLSX.

Данные, считанные с изображений и чертежей, ставь со статусом «допущение»
с пояснением «считано с чертежа, проверить», пока инженер не подтвердит.

## Шаг 2. Составь vor.json

Формат: `references/format.md`, пример: `assets/vor.example.json`.

Правила для каждой строки:

1. **Формула, а не готовое число.** Пиши подсчёт из размеров документа:
   `"(2*(24+36)+24) × 0,6 × 1,2"`. Допустимы числа, `+ - × /`, скобки и ссылки
   на другие строки `@id` (например, засыпка `@выемка - @бетон`). Число без формулы (`qty`)
   только если оно прямо указано в документе, например в спецификации.
2. **Источник.** `ref` — id документа из `documents`, `loc` — место: «стр. 3, п. 2.1»,
   «лист КЖ-3, ось Б», «таблица 2, строка 5».
3. **Статус:**
   - `подтверждено` — все размеры есть в документе;
   - `допущение` — что-то принято тобой (коэффициент, расход, доля ручной разработки);
     поясни в `assumption`, откуда взято и что уточнить;
   - `нет данных` — посчитать нельзя; объясни в `missing`, какого документа не хватает.
     Количество не ставь и не угадывай.
4. **Код прайса** (`code`), если работа есть в прайс-листе компании (навык `prices`,
   команда `find`). Тогда при переходе к КП цена подставится сама.
5. Нормы расхода, коэффициенты разрыхления, доли ручных работ без документа —
   всегда «допущение» с указанием, кто должен подтвердить.

## Шаг 3. Собери и проверь

```bash
uv run <папка навыка>/scripts/build_vor.py projects/<объект>/input/vor.json
uv run <папка навыка>/scripts/check_vor.py <vor.json> <VOR_....xlsx> <VOR_....pdf>
```

Получатся Excel (количества считаются формулами, допущения жёлтые, строки без данных
красные) и PDF с местом для подписей «Составил» и «Проверил». Выдавать можно только
при результате проверки «пройдена». Если в vor.json указан `brand`, применяется
фирменный стиль.

## Шаг 4. Отчитайся

Покажи пользователю: пути к файлам, таблицу строк с количествами и статусами,
список допущений и список недостающих данных с тем, у кого их запросить.

## Шаг 5. Переход к КП (если нужно)

```bash
uv run <папка навыка>/scripts/vor_to_kp.py <vor.json> --out <kp.json> --number <номер КП> \
    --price-list data/prices.xlsx [--brand data/brand.json]
```

Строки без данных в КП не попадают и печатаются в разделе «Не включено в стоимость».
Допущения переходят в допущения КП. Ставки (накладные, прибыль, НДС) скрипт не придумывает:
если их нет в фирменном шаблоне, спроси у пользователя и впиши в kp.json. Дальше навык `kp`.

## Чего не делать

- Не угадывай размеры, которых нет в документах. Лучше строка «нет данных».
- Не записывай итоговые количества вручную вместо формулы.
- Не меняй статус на «подтверждено» без документа.
- Не правь готовые xlsx/pdf: меняй vor.json и пересобирай.
