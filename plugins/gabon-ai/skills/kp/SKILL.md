# КП: коммерческое предложение (PDF + Excel + Word)

Сначала прочитай общие правила GABON AI: `${CLAUDE_PLUGIN_ROOT}/rules/RULES.md`.

Арифметику, формулы и оформление делают скрипты из папки `scripts/` рядом с этим файлом.
Твоя работа: собрать корректные исходные данные, запустить сборку, запустить проверку
и честно отчитаться. Сам суммы не считай и в документы не вписывай.

## Шаг 1. Найди папку проекта

Работаем в папке проекта пользователя, например `projects/<объект>/`:

```
projects/<объект>/
  input/     исходники заказчика (PDF, Excel, Word, чертежи) и kp.json
  output/    готовые КП
  data/      company.json, логотип, прайс-листы (или общая data/ на уровень выше)
```

Если реквизитов компании нет, скопируй `assets/company.example.json` в `data/company.json`
и попроси пользователя заполнить. Без реквизитов КП не выпускается.

Если в `data/` есть `brand.json` (навык `brand`), укажи его в kp.json полем `brand`.
Тогда оформление, бланк, условия и тексты по умолчанию возьмутся из него.

## Шаг 2. Собери исходные данные

1. **Объёмы**: только из документов пользователя (ВОР, дефектная ведомость, проект,
   спецификация) или из его слов. Если объём рассчитан тобой из размеров, укажи это
   в `assumptions` с формулой расчёта.
2. **Цены**: если у компании есть прайс-лист (`data/prices.xlsx`, навык `prices`),
   укажи в kp.json `price_list`, а в позициях только `code` и `qty`. Цена, единица, вид затрат
   и источник с датой подставятся автоматически. Код ищи командой `prices.py find`.
   Без прайс-листа — строго в этом порядке:
   прайс-лист компании → КП поставщиков → лицензионная база (АВС-4 и т. п., через экспорт) →
   цена, названная пользователем. В поле `source` пиши, откуда цена и на какую дату.
   Источника нет — не придумывай цену: внеси позицию в `missing_data` и спроси пользователя.
3. **Ставки**: накладные, прибыль и НДС — из данных компании или от пользователя.
   Для НДС обязательно поле `vat_source`. Ставку НДС «по памяти» не подставляй.
4. Все цены в позициях без НДС. Если поставщик дал цену с НДС, переведи её в цену без НДС
   и запиши это в `source`.
5. Каждой позиции укажи вид затрат: `работа`, `материал`, `механизм`, `транспорт`,
   `комплекс` (работа с материалами одной ценой), `прочее`.

Задавай вопросы только о том, без чего КП невозможно: заказчик, объект, объёмы,
источник цен, ставки. Остальное оформи как допущения.

Формат файла `kp.json` описан в `references/input-format.md`,
полный пример лежит в `assets/kp.example.json`.

## Вариант: пользователь работает в Excel-шаблоне

Создай пустой шаблон в папке проекта:
`uv run ${CLAUDE_PLUGIN_ROOT}/skills/kp/scripts/make_template.py projects/<объект>/input/KP_template.xlsx`.
Пользователь заполняет жёлтые ячейки, все суммы считают
формулы Excel. Из заполненного шаблона фирменный PDF собирается так:

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/skills/kp/scripts/xlsx_to_kp.py projects/<объект>/input/<шаблон>.xlsx
```

Получится `kp.json` рядом с файлом. Дальше шаги 3–4 как обычно.

## Разбор чужого или старого КП

Если пользователь даёт готовое КП (PDF, Excel) как образец или на проверку:

1. Исходный файл не изменяй. Работай с копией данных.
2. Пересчитай каждую строку (кол-во × цена) и итоги скриптом, а не в уме.
3. Отдельно сообщи о расхождениях: строка, сумма в КП, пересчёт, разница.
4. Проверь признаки подгонки: «круглый» итог с НДС, итог без НДС = итог / 1,16,
   цена в строке не совпадает с суммой / количество.
5. Цены из образца не являются рыночными расценками. Если они используются,
   в `source` пиши номер и дату образца с пометкой «образец».
6. Реквизиты компании из образца переносятся в документы только по явному указанию пользователя.

## Шаг 3. Собери КП

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/skills/kp/scripts/build_kp.py projects/<объект>/input/kp.json
```

Файлы появятся в `projects/<объект>/output/`: Excel с формулами, PDF для отправки и Word
для правки текста (то же содержание и те же суммы). Фирменный бланк PDF в Word не переносится:
в Word шапка собирается из логотипа и реквизитов. Если Word не нужен: `--no-docx`. Если скрипт сообщает об ошибках
в исходных данных, исправь `kp.json` (или спроси пользователя) и запусти снова.
Если `uv` не установлен, попроси пользователя установить его: https://docs.astral.sh/uv/

## Шаг 4. Проверь

```bash
uv run ${CLAUDE_PLUGIN_ROOT}/skills/kp/scripts/check_kp.py <kp.json> <KP_....xlsx> <KP_....pdf> <KP_....docx>
```

Проверка независимо пересчитывает все формулы Excel и сверяет их с исходными данными,
ищет ошибки формул и проверяет, что PDF открывается и содержит те же итоги.
Выдавать КП можно только при результате «пройдена». Дополнительно сам проверь:
единицы измерения соответствуют виду работ, нет дублей позиций, объёмы совпадают
с документами заказчика.

## Шаг 5. Отчитайся пользователю (по-русски, простыми словами)

- пути к PDF, Excel и Word;
- если пользователь правил текст в Word, суммы в Word не пересчитываются: цифры меняются только в kp.json с пересборкой;
- итого без НДС, НДС, всего с НДС;
- допущения и недостающие данные;
- результат проверки;
- напоминание: КП является проектом и требует проверки и утверждения ответственным специалистом.

Если пользователь просит «подогнать» итог под сумму, не меняй цены молча:
покажи, какие позиции или ставки нужно изменить и на сколько, и делай только после согласия.

## Что не делать

- Не выдумывай цены, расценки, шифры норм, объёмы, подписи.
- Не редактируй готовые xlsx/pdf вручную: меняй `kp.json` и пересобирай.
- Не убирай пометку `sample: true` с тестовых данных.
