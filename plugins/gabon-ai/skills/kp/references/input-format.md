# Формат kp.json

Все суммы считаются скриптом. Цены указываются **без НДС**, в тенге.

| Поле | Обяз. | Описание |
|---|---|---|
| `number` | да | Номер КП, например `КП-2026-015` |
| `date` | да | Дата КП, `ГГГГ-ММ-ДД` |
| `valid_days` | нет | Срок действия в днях |
| `currency` | нет | По умолчанию `KZT` |
| `company` | да | Путь к `company.json` (относительно kp.json) или объект с реквизитами |
| `object.name` | да | Наименование объекта; `object.address` по желанию |
| `basis` | нет | Основание: письмо, тех. задание, ВОР № … |
| `intro` | нет | Вводный абзац |
| `rates.overhead_pct` | да | Накладные, % от прямых затрат |
| `rates.profit_pct` | да | Прибыль, % от (прямые + накладные) |
| `rates.vat_pct` | да | НДС, %. Для неплательщика НДС укажите `0` |
| `rates.vat_source` | да | Основание ставки НДС и дата проверки |
| `rates.overhead_source`, `rates.profit_source` | нет | Откуда взяты ставки |
| `sections[]` | да | Разделы: `title` и `items[]` |
| `terms` | нет | Объект `duration`, `payment`, `warranty`, `start` или список строк |
| `assumptions[]`, `exclusions[]`, `missing_data[]` | нет | Списки строк |
| `sample` | нет | `true` — водяной знак «ОБРАЗЕЦ» |
| `brand` | нет | Путь к фирменному шаблону `brand.json` (навык brand): цвета, логотип, бланк, тексты по умолчанию |
| `price_list` | нет | Путь к прайс-листу компании (относительно kp.json), например `../data/prices.xlsx` |
| `price_max_age_days` | нет | Через сколько дней цена считается устаревшей, по умолчанию 90 |
| `numbering` | нет | `section` — номера 1.1, 1.2 (по умолчанию); `continuous` — сквозные 1, 2, 3, разделы без слова «Раздел» |
| `rates.amount_decimals` | нет | `2` — суммы до тиын (по умолчанию), `0` — до тенге |
| `client.name` | нет | Если пусто, в документе остаётся поле «не указан» и замечание |

## Позиция (`items[]`)

| Поле | Обяз. | Описание |
|---|---|---|
| `name` | да | Наименование работы или затраты |
| `unit` | да | `м`, `п.м`, `м2`, `м3`, `т`, `кг`, `шт`, `компл`, `маш.-ч`, `чел.-ч`, `рейс`, `км`, `смена`, `услуга` … |
| `qty` | да | Количество > 0 |
| `price` | да | Цена за единицу без НДС ≥ 0 |
| `kind` | да | `работа`, `материал`, `механизм`, `транспорт`, `комплекс` (работа с материалами), `прочее` |
| `source` | да | Источник цены и дата: «Прайс ТОО … от 01.10.2026», «КП поставщика № …» |
| `code` | нет | Код из прайс-листа. Тогда `price`, `unit`, `kind`, `source` и `name` можно не указывать: они подставятся из прайса |
| `price_override_reason` | нет | Обязателен, если при указанном `code` цена в КП отличается от прайса |

Пример позиции с кодом: `{ "code": "МН-005", "qty": 86 }`.
Если в КП указаны `unit` или `kind`, они должны совпадать с прайсом, иначе это ошибка.

## Порядок расчёта (одинаковый в Excel и PDF)

1. Сумма позиции = ОКРУГЛ(кол-во × цена; n), где n = `amount_decimals`
2. Прямые затраты = сумма всех позиций
3. Накладные = ОКРУГЛ(прямые × % накладных; n)
4. Прибыль = ОКРУГЛ((прямые + накладные) × % прибыли; n)
5. Итого без НДС = прямые + накладные + прибыль
6. НДС = ОКРУГЛ(итого без НДС × % НДС; n)
7. Всего с НДС = итого без НДС + НДС

Если у компании другая методика (например, накладные только от ФОТ), это изменение
вносится в скрипт и в эту таблицу, а не вручную в Excel.

## Excel: что внутри

- **КП**: позиции с формулами, итоги, структура затрат по видам, контрольная строка (должна быть 0).
- **Параметры**: ставки. Измените ставку здесь, и Excel пересчитает всё КП.
- **Допущения**: допущения, исключения, недостающие данные, замечания проверки.
- Именованные ячейки: `KP_DIRECT`, `KP_OVERHEAD`, `KP_PROFIT`, `KP_SUBTOTAL`, `KP_VAT`, `KP_TOTAL`, `KP_CONTROL`.
