# Смета: локальный расчёт и проверка смет подрядчиков

Скрипты в `scripts/` рядом с этим файлом. Арифметику делают они.

## Важно про нормативные сметы

Официальную нормативную смету по сметным нормам РК этот навык не составляет: шифры
расценок, индексы и нормы берутся только из лицензионной программы (АВС-4 и др.).
Навык делает **коммерческий расчёт ресурсным методом** и умеет **проверять и сравнивать**
сметы, в том числе выгрузки из АВС-4 в Excel. Так и говори пользователю.

## Часть 1. Локальная смета

Данные в папке проекта:
- `smeta.json` — позиции, ставки (формат: `references/format.md`, пример: `assets/smeta.example.json`);
- `data/cards.json` — калькуляции: нормы расхода ресурсов на единицу работы с источником
  (пример: `assets/cards.example.json`);
- `data/prices.xlsx` — цены ресурсов (навык `prices`): ставки чел.-ч, маш.-ч, материалы, перевозки.

Порядок:
1. Количества бери из ВОР (`"vor": "vor.json"` и у позиции `vor_id`). Без ВОР —
   `qty` и обязательно `qty_source`.
2. Для каждой работы нужна калькуляция: какие ресурсы и сколько на единицу.
   Нормы расхода **не придумывай**. Источники: калькуляции компании, технологические карты,
   паспорта материалов, ресурсная часть выгрузки АВС-4, данные пользователя.
   Если нормы нет — спроси пользователя или предложи значение явно как допущение
   и запиши это в `source` («допущение: … уточнить»).
3. Цены ресурсов — по кодам прайс-листа (`code`) или с `price_source`.
4. База накладных и прибыли: `direct` (от прямых затрат) или `fot` (от ФОТ).
   Какую базу и проценты применяет компания, спроси у пользователя.
5. Собери и проверь:

```bash
uv run <папка навыка>/scripts/build_smeta.py projects/<объект>/input/smeta.json
uv run <папка навыка>/scripts/check_smeta.py <smeta.json> <SMETA_....xlsx> <SMETA_....pdf>
```

Excel: лист «Смета» (позиции и их ресурсы с формулами), «Ресурсы» (ресурсная ведомость
для заказа материалов), «Параметры» (ставки, при изменении Excel пересчитывает всё).
PDF: позиции с разбивкой на ФОТ, машины, материалы, транспорт, итоги, ресурсная ведомость.

## Часть 2. Проверка сметы или КП подрядчика

1. Исходный файл подрядчика не изменяй.
2. Excel подрядчика импортируй:

```bash
uv run <папка навыка>/scripts/import_estimate.py <файл подрядчика.xlsx> --out projects/<объект>/input/contractor.json --contractor "ТОО …"
```

   Если колонки не найдены, посмотри файл и укажи их: `--map name=B,unit=C,qty=D,price=E,amount=F`.
   Если цены с НДС: `--prices-include-vat`. PDF подрядчика перенеси в тот же JSON вручную
   (формат в `references/format.md`), каждую строку с номером `row` из документа.
   Открой contractor.json и проверь, что разделы, позиции и итоги распознаны верно.
3. Сравни с нашей сметой или КП:

```bash
uv run <папка навыка>/scripts/compare.py --ours <smeta.json или kp.json> --contractor <contractor.json> --out projects/<объект>/output
```

   Сопоставление идёт по полю `match` в contractor.json (номер нашей позиции, например «2.3»),
   затем по коду, затем по похожести названия при той же единице. Пары с пометкой
   «проверьте сопоставление» посмотри сам; при ошибке впиши `match` и запусти снова.
4. Отчитайся: разница итогов, ошибки в документе подрядчика (арифметика, НДС, подгонка
   итога), крупнейшие отклонения по объёму и цене, лишние и пропущенные позиции.

По умолчанию наши цены приводятся к полным без НДС (накладные и прибыль распределены
пропорционально), потому что подрядчики дают цены «под ключ». Для сравнения прямых затрат:
`--basis direct`. Пороги отклонений: `--price-tol 10 --qty-tol 2` (%).

## Чего не делать

- Не придумывай шифры норм, индексы, коэффициенты и нормы расхода.
- Не называй коммерческий расчёт нормативной сметой.
- Не делай выводов о завышении без указания, с чем сравнивали (наша смета, прайс, дата цен).
- Отклонения — повод для вопросов подрядчику, а не доказательство нарушения.
